Save, destroy & restore — repeat the cycle

Use these commands in a terminal on the deployment host, from this repository. They follow the cluster selected below. Copying a command does not run it.

Running cluster→New snapshot + destroy→Restore + use↻Repeat

  1. Save the cluster, then destroy it

    The script gracefully stops the nodes and snapshots every disk. Teardown proceeds only if the snapshot set completes. Type yes when asked to confirm deletion.

  2. Choose a completed snapshot set

    List saved sets and choose the new set marked ready to restore your latest changes. Older sets remain available too.

  3. Restore and keep the cluster running

    Restore the saved node disks, settings and credentials. Terraform recreates the load balancer, network, firewalls and Cloudflare records. Type restore when prompted; wait for health checks to pass.

    --no-autodestroy keeps the restored cluster running. Its load balancer may receive a new IP; DNS is updated.

  4. Make changes, then repeat step 1

    Restoring keeps the source snapshots. The next snapshot-enabled teardown creates a new set containing your latest changes: snapshot A → restore A → change → snapshot B → restore B.

    Keep .cluster-snapshots/, your configuration, credentials and original SSH key. Named-cluster bundles live under .work/NAME/.cluster-snapshots/.

    Snapshots and retained IPv4 addresses remain billable. Old protected snapshots are not cleaned up automatically.

Already have snapshots in Hetzner? Discover or import them

Recorded set: use step 2 above, then restore its set ID. There is no need to import it again.

Unrecorded image: use this review workflow. A disk image alone cannot supply the original load balancer, DNS settings, IPs or installation identity.

  1. Discover available Hetzner snapshots. Check each image's original source server and whether it already belongs to a local recorded set.
  2. Create and edit the review file. Set one image and both original Primary IP IDs for every node. Point it at the original Terraform state, configuration file and matching installation artifacts. For a named cluster, the file is created in its isolated workspace.

    The file starts with zero IDs and confirmations set to false. Only confirm if all nodes were snapshotted while stopped at the same recovery point and the artifacts belong to that exact cluster incarnation. The image metadata cannot prove this for you. If original IPs or matching files are lost, stop and use a separate recovery procedure.

  3. Validate before recording anything. This checks the complete node mapping, image provenance, original IPs and cluster files. It performs no cloud changes or restore.
  4. Record the reviewed set. Type import when prompted. This copies matching artifacts into a new local set; it does not boot, stop, delete or relabel anything in Hetzner. Existing sets are never overwritten.

    Then use the new import-… set ID in step 3. Restore still refuses to replace a running cluster. Images stay in Hetzner and continue to incur charges; importing does not change their deletion protection.

This procedure requires an installed, healthy cluster and its original workspace. Attached volumes, private node networks and unmanaged/autoscaled nodes are unsupported; external storage needs a separate backup. Stop the resident autoscaler before snapshotting. Use snapshot-enabled teardown each time; ordinary Destroy does not create a new snapshot unless the saved snapshot preference is enabled.
